# Player ratings

Lobo requested two independent Discord rating role systems and Portal ELO from all Portal games.

Portal ELO starts each player at 1500 and applies symmetric K=32 Elo to the recorded win, draw, or loss. Objective and victory point margins do not multiply the change. Players are provisional until ten completed games. Ratings retain floating point precision internally; displays and role bands use the rounded rating. Ratings do not reset each season. After 30 calendar days without a completed rated game, ratings above 1500 lose (last post-game rating − 1500) / 150 per day. Day 31 applies the first deduction and day 180 reaches exactly 1500. The daily rate stays fixed for that inactivity interval; it does not compound. Ratings at or below 1500 do not decay or increase. Every player is marked Inactive at 180 days without a rated game, regardless of rating. A returning rated game first settles inactivity, then applies normal K=32 Elo, and restores Active status with a new 30-day grace period. Dates use the America/New_York calendar, with day differences calculated using UTC date-only values to avoid daylight-saving drift.

`shared/portal-elo.mjs` replays the entire published canonical game history (all types, events, and dates), plus confirmed live Aurora VII campaign reports. Campaign practice, rejected, pending confirmation, correction requested, unapproved late, and unapproved duplicate reports are excluded. Canonical games use their persistent Game ID; campaign IDs are namespaced. Identical repeated IDs count once; conflicting IDs or invalid outcomes/dates stop publication. Games sort by played date and then persistent ID with numeric ordering. For games recorded on the same day, this stable tie break supplies the order because public snapshots do not expose a game start time. Corrections, additions of old results, and removals therefore recalculate all later games, including historical inactivity intervals. The policy applies to existing recorded inactivity; it is not delayed until 30 days after deployment. `calculatePortalElo(games, { asOf })` allows deterministic replay; production defaults to the current Eastern date. Each final projection recomputes from original game records rather than a previously decayed rating, so minute refreshes and restarts cannot double-deduct. `decayHistory` records deductions separately, with before/after values, days, fixed rate and sequence; deductions never count as games, losses or last-game changes. The per-player `inactivity` object includes status, days without play, current-interval deduction, daily rate, and start/inactive dates. `totalDecay` sums all replayed inactivity intervals.

The LLH worker checks the current Portal snapshot and confirmed campaign ledger every minute. Published canonical games enter at the next Portal snapshot; campaign reports enter after confirmation and the next worker check. `/api/player-ratings` serves the same calculation used for roles. `/elo` shows the leaderboard, active/inactive filter and labels, source cutoff, per-game rating history, separate inactivity deductions and a trend including both games and decay. The Discord `/elo` command reports the same inactivity status and deduction. The worker recalculates every minute even when the source snapshot is unchanged, so daily decay and 180-day status changes do not require a new game or snapshot. Portal rating-band roles use the decayed rating. Player profiles link to it. A source failure reports unavailable rather than publishing incomplete ratings; a Discord permission error does not block a valid leaderboard.

Infinity the Meta's public `players/` API supplies its independent Glicko-2 ratings. The importer includes inactive and provisional players, paginates the complete directory, validates unique person IDs and a single published run, and refreshes hourly. Import failure preserves existing Meta roles and is reported. Meta ratings never seed or change Portal ELO.

Discord bands use `Portal ELO` and `Meta Rating` prefixes: Under 1000, 1000–1199, 1200–1399, 1400–1599, 1600–1799, 1800–1999, 2000–2199, 2200+. Matched Portal members with no completed games receive `Portal ELO Unrated`. Roles have no permissions, are not mentionable, and are not hoisted. The worker only replaces its tracked rating roles, adds a replacement before removing the previous band, verifies changes, and retries failures. It never changes nicknames or unrelated roles.

Identity matching reuses explicit Top 40 and campaign Discord links and exact unique usernames/display names. It does not guess based on partial names. Ambiguities and unmatched accounts remain in the private `/ratings status` report. Manage Server is checked on every ratings command. `/ratings link account:<member> player:<exact portal player> meta_id:<pin:...>` saves a confirmed link; `meta_id` is optional. `/ratings sync` reruns the process. The ledger persists on the Railway volume as `player-ratings.json`. `/ratings/status` exposes counts only; the public ratings response excludes Discord account IDs and private campaign information.

Validation: `npm run test:player-ratings`, the LLH and Aurora game regressions, TypeScript and the production build. The rating test is also run during the bot image build.
